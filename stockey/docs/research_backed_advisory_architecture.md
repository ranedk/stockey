# Research-Backed Advisory Architecture

Updated: 2026-06-22

This note records the current research direction for upgrading Stockey. It is not a benchmark result for Indian equities; it is the engineering direction implied by recent LLM-agent and regime/context literature.

## Findings

1. LLM trading agents should not be treated as standalone traders.
   - StockBench reports that most evaluated LLM agents struggle to beat a simple buy-and-hold baseline in realistic multi-month trading, even though they receive prices, fundamentals, and news.
   - Profit Mirage highlights leakage and benchmark/generalization issues in LLM financial agents.
   - FINSABER reports that LLM timing strategies can look strong in narrow evaluations but lose robustness over longer periods and broader universes; it also finds poor behavior around market regimes, including underparticipation in bull markets and excessive risk in bear markets.
   - Architecture implication: keep LLMs away from direct broker authority. Use them for structured extraction, hypothesis generation, contradiction checks, and context overlays.

2. LLM outputs should be aggregated and validated.
   - Recent disclosure-agent work uses multiple zero-shot agents to produce sentiment/confidence/rationale features, then aggregates them with a lightweight meta-classifier.
   - Architecture implication: prefer event tensors, overlay candidates, and learned/deterministic aggregation over a free-form "LLM says buy" path.

3. A single global regime is too blunt.
   - Regime-aware portfolio work argues that sector-specific forecasting and allocation conditioned on regime/context is more robust than pooled, regime-agnostic modeling.
   - Architecture implication: market context should be multi-layered: broad breadth/stress, sector/theme sensitivity, news/macro event clusters, and symbol-level technical confirmation. A global regime label can remain diagnostic, but it should not be the primary buy/sell gate.

4. News and macro should change the watch universe before they change trade execution.
   - News-aware trading work commonly combines LLM news signals with market data before a downstream policy/optimizer acts.
   - Architecture implication: news/macro should create watchlist pressure, sector/theme candidates, reduce-risk candidates, and wait signals. Entry/exit still requires technical, liquidity, risk, and lifecycle confirmation.

5. Research validation matters more than model complexity.
   - Backtest-overfitting work in financial ML emphasizes purging, embargo, and combinatorial purged cross-validation to reduce leakage and false discovery in time-dependent labels.
   - Architecture implication: every new context family, split, prompt, or LLM-derived signal must remain research-only until it beats technical-only baselines after costs across enough symbols, dates, horizons, and rolling windows.

6. Raw up-market performance is not alpha.
   - Recent leakage-controlled LLM-agent benchmarks report that apparent LLM trading returns can be explained largely by passive market/style exposure rather than persistent stock-selection alpha.
   - Architecture implication: context overlays and LLM-derived watch/de-risk signals must be evaluated against benchmark excess return, not only raw forward return. A signal that works only because the whole market moved should stay research-only or be treated as harmful/noisy.

7. Regime should be layered attribution, not one global switch.
   - Asset-specific regime forecasting research argues against one broad economic label for every asset.
   - Architecture implication: Stockey should keep global breadth/stress labels diagnostic, but validate sector, symbol, source-family, and context-class behavior independently before allowing any bounded influence.
- Implementation implication: missing-BUY diagnostics now report broad benchmark participation from `advisory_market_regime` as attribution context. If NIFTY is up but no BUY rows exist, the system should investigate technical-entry confirmation, stale artifacts, context-overlay conversion, and downstream consolidation before changing any global regime policy.
- Implementation implication: missing-BUY diagnostics now also split upstream constructive candidates by effective technical setup archetype. This makes it visible whether the system has many watch-breakout, near-pivot, pullback, or confirmed-entry rows and whether those rows survive downstream consolidation, instead of attributing underparticipation to one global regime label.
- Implementation implication: recommendation diagnostics now emits a `layered_underparticipation_attribution` contract through both `python -m advisory.recommendation_diagnostics` and the read-only `/api/research/recommendation-diagnostics` operator endpoint. It ranks the likely missing-BUY layer across candidate freshness, bounded context refresh, technical-entry confirmation, context source-to-signal conversion, downstream consolidation, and hard macro/market evidence. In a rising benchmark, this makes the first explanation technical/context/consolidation evidence rather than a single global regime label.
- Implementation implication: the same diagnostic now loads point-in-time signal-quality summary rows and separates context evidence that is `benchmark_beta_not_overlay_alpha` or `needs_benchmark_attribution`. In a rising benchmark, those rows become a research blocker with the rolling-window split-diagnostic command, not a reason to loosen global regime or context policy.
- Implementation implication: `advisory.signal_quality_family_report` now emits a compact `promotion_readiness` gate over technical-only versus technical-plus-context outcomes. It separates candidate-helpful families from benchmark-beta-only, benchmark-unattributed, low-data, and horizon-inconsistent families, and returns research-only queue actions for promotion review, split diagnostics, or data collection. This keeps news/macro/bhavcopy/announcement/company-memory influence reviewable without letting raw positive context become policy authority.
- Implementation implication: runtime fallback consumers keep the same evidence boundary. When watchlist-builder or action-consolidation cannot use persisted fast context reliability and falls back to full signal-quality summaries, they now carry benchmark/excess-return fields and `promotion_readiness` into diagnostics instead of degrading to raw-return or broad-family labels.
- Implementation implication: the same diagnostic now emits `research_context_policy_alignment`. This read-only contract combines hard-gate exposure, layered context labels, source-family reliability, benchmark-attribution blockers, and reviewed-rule runtime eligibility into one status such as `single_regime_policy_exposed`, `layered_context_attribution_blocked`, `layered_context_metadata_incomplete`, or `layered_context_policy_aligned`. It is an audit summary only: it cannot change recommendations, portfolio rows, config, or broker behavior.
- Implementation implication: the context-gate policy audit now includes hypothesis/playbook planning gates as well as rule-engine and action-consolidation gates. Broad `HYPOTHESIS_MARKET_CONTEXT_REGIME_LABEL_HARD_BLOCK_ENABLED` drift is therefore visible as a single-regime hard-gate exposure before it can silently suppress watch or wait-signal generation.
- Implementation implication: the same diagnostic path now emits `context_to_entry_pipeline`, a read-only funnel from context source rows to persisted context watchlist intake, bounded context-refresh signals, action-level context pressure, constructive/confirmed technical candidates, and final BUY/BUY_MORE survival. The companion `context_watchlist_intake` section splits persisted context rows into active watch pressure, `WATCH_BREAKOUT` pressure, and suppressed identity/reliability/negative-context audit rows. The funnel also distinguishes fast direct context-refresh pressure from a persisted watchlist snapshot: `context_direct_refresh_without_persisted_watchlist` means watcher/pre-advisory refresh created review-only Action Queue pressure before full watchlist reconciliation, not that the context engine or regime layer failed. This makes it visible whether news, macro, bhavcopy, and announcement evidence stopped at source conversion, watchlist intake/removal, signal refresh, technical-entry confirmation, or downstream consolidation without granting context-only trading authority.
- Implementation implication: `context_to_entry_pipeline` now also reports `source_family_attribution`, splitting announcement, macro, bhavcopy, exchange, and theme context by source rows, active authorized rows, conversion targets, kept targets, reliability/policy suppression, watchlist rows, and review-only action pressure. A family can therefore be debugged as reliability-suppressed, conversion-blocked, watchlist/action-refresh blocked, or successfully reaching pressure without loosening a global regime gate.
- Implementation implication: `context_to_entry_pipeline` now includes `positive_context_entry_blocker`, a compact read-only attribution that ranks why positive news/macro/announcement/bhavcopy pressure did not become BUY: stale/missing technical features, hard OHLCV blockers, candidate-generation gaps, pending technical trigger, or downstream risk/lifecycle/transition consolidation. This keeps rising-market underparticipation debugging focused on the layer that failed instead of loosening one global regime gate or granting context-only BUY authority.
- Implementation implication: `all_context_to_entry_repair.sh` is the bounded operator/cron repair for that attribution. It refreshes review-only context signals, reconciles durable context-watch rows, runs targeted context-watch technical refresh for only active context symbols, runs rules-through-actions only, refreshes the Action Queue, and reruns diagnostics before the full post-close advisory. This addresses stale context-watch, stale technical-confirmation, and candidate bottlenecks without making context evidence a direct BUY signal.
- Implementation implication: context-watch technical precheck now separates broker/security identity coverage from stale or missing technical features. If Dhan/company-master identity is missing, diagnostics point to master repair. If identity is available but rows are stale/missing, diagnostics point to bounded technical feature refresh and advisory rerun. This prevents "no BUY in a rising market" from being incorrectly attributed to a single global regime label before the point-in-time technical-confirmation layer is current.
- Implementation implication: `advisory.technical_features` now persists per-symbol refresh/build outcomes in `advisory_technical_feature_refresh_status`, and recommendation diagnostics consumes those rows. Repeated Dhan 400, no-new-data, zero-row, or post-build missing-row states therefore become explicit data blockers in the context-to-entry funnel rather than silent stale-feature artifacts. The bounded `--targeted-context-refresh` mode refreshes Dhan OHLCV and technical rows for active context-watch symbols without the slower Sharpely fundamentals or peer-sync work, so stale technical confirmation can be repaired before changing regime/context policy. Diagnostics also checks latest Dhan daily OHLCV availability before selecting the repair date; if Dhan lags the exchange calendar, the command is pinned to the latest Dhan-backed date while newer failed refresh attempts remain visible. Context watchlist rebuilds consume this status too: hard no-history blockers are rejected as audit rows, while stale-history partial blockers remain visible but receive no technical priority bonus and explicitly carry `technical_fresh_entry_allowed=false`. Hard no-history failures also create open `dhan_ohlcv_history_unavailable` operator issues, those issues resolve only after local Dhan daily history appears, and repeated open issues become durable context-watch exclusions after the configured attempt threshold.
- Implementation implication: when the read-only context-overlay or causal-memory preview would emit review-only signals, recommendation diagnostics recommends the bounded `advisory.signal_refresh` command before the long full-advisory reconciliation only if the matching signal-refresh sync state is missing, stale, wrong-as-of, incomplete, or authority-unsafe. If the persisted bounded refresh already covers the preview with review-only/no-broker authority, diagnostics skips the redundant refresh and points to full advisory reconciliation. The preview remains idempotent and still has no BUY/SELL, portfolio, sizing, or broker authority.

8. Entity identity is part of signal quality.
   - LLM/news extraction work highlights that static model knowledge is not enough for company-ticker mapping because companies, symbols, and businesses change.
   - Architecture implication: LLM-derived news, announcement, peer, and sector signals must be validated against current point-in-time company/security masters before entering watchlist, context-overlay, or action-reason contracts. Missing or ambiguous identity should become a visible source blocker, not a silent fallback or hallucinated symbol.

9. LLM decision quality requires provenance, not just final answers.
   - Recent agent-provenance work argues that final-answer accuracy cannot explain which evidence supported a claim, whether tools were justified, how memory influenced the result, or where a failure came from.
   - Architecture implication: every LLM-derived event tensor, hypothesis plan, company-memory review, context overlay, and action-candidate influence should carry a typed evidence/provenance contract: source rows, tool calls, retrieved memory, prompt/schema version, claims, contradictions, invalidations, and downstream action influence.

10. Direct LLM action emission is unstable without a stateful policy layer.
   - Recent trading-strategy benchmarks report high run-to-run instability, inconsistent action sequences even under deterministic decoding, and rapid buy/sell flipping when LLMs directly emit trading actions.
   - Architecture implication: Stockey should not ask an LLM to emit executable BUY/SELL decisions from a current snapshot. LLMs may propose evidence, pressure, and hypotheses; a stateful policy layer must own cooldowns, position state, prior actions, thesis status, stop/target state, and transition legality.

11. Event memory should merge, track, and decay events over time.
   - Event-memory stock forecasting work converts news streams into structured temporal event sequences, merges duplicate/fractured events, and retrieves historically analogous event patterns.
   - Architecture implication: Stockey should move from per-document interpretation toward a causal event memory that merges same-day duplicates, links follow-up announcements/news, tracks event freshness/decay by class and sector, and exposes the current event state to LLM/company-memory/action-reason paths.

## Design Rules Adopted

1. Do not let a single regime label zero out recommendations.
   - Broad market context can reduce size, flag risk, or demand extra confirmation.
   - Sector, theme, macro, exchange-event, bhavcopy, and announcement overlays should be evaluated independently because different sectors can react differently to the same macro/news shock.

2. Convert unstructured text into compact, point-in-time evidence before decisioning.
   - LLM outputs should become event tensors, context overlays, wait signals, source-quality annotations, contradictions, and review notes.
   - Free-form LLM "buy/sell" conclusions should not directly reach portfolio or broker layers.
   - Action consolidation enforces this as a fail-closed boundary: event-policy, company-memory, playbook, manual-review wait-signal, and fast signal-refresh sources are sanitized before ranking/persistence, so any broker-capable action or broker-order field from those review-only sources is downgraded and audited.

3. Split noisy context families before trusting them.
   - If `announcement_context`, `exchange_context`, `bhavcopy_context`, `theme_context`, or `macro_context` is mixed or horizon-sensitive, split by event class, direction, pressure class, sector, macro signal, or rule id.
   - Treat helpful splits as research hypotheses, harmful splits as negative controls, and low-data splits as data-collection items.

4. Promote only after stable evidence.
   - Source-family or split influence must beat `technical_only` after costs.
   - Source-family or split influence must also beat passive benchmark movement after costs; raw positive return during an up-market is insufficient.
   - Evidence must be point-in-time, leakage-controlled, and stable across rolling windows before it can even create manual promotion-review rows.
   - Policy auto-promotion and broker execution remain disabled for all signal-quality research artifacts.

5. Attribute before trusting LLM/context decisions.
   - Promotion reviews must show whether a candidate source added stock/sector-specific value or merely loaded on market beta.
   - Positive/watch overlays should require positive excess return after costs before they can be classified as opportunity candidates.
   - Negative/de-risk overlays should require benchmark-relative protection after costs before they can be classified as protective candidates.

6. Validate identities before accepting extracted signals.
   - LLM-extracted tickers, peers, sectors, and affected entities must resolve through the project company/security master or be marked as an identity/source issue.
   - Do not let unresolved extracted symbols create watch rows, action candidates, or context-overlay support/conflict counts. They can remain audit evidence until the mapping is repaired.

7. Persist provenance for every LLM-derived influence.
   - A persisted LLM output is incomplete unless it states what it read, what it inferred, what it ignored, what it contradicted, and what downstream influence it is allowed to have.
   - Provenance must be compact enough for hot paths: store hashes/pointers for bulky evidence, typed IDs for source rows, and small claim/evidence/contradiction summaries in Postgres.
   - `advisory.action_evidence_provenance` now turns final `advisory_action_recommendations.recommendation_reason_json` contracts into typed final-action-to-evidence nodes, including event-policy LLM evidence, compact event-policy claims/wait conditions/operator questions, playbook claims/actions, company-memory claims/risks/evidence references/wait conditions, context overlays, causal event memory, conflict resolution, transition stability, technical, risk, macro, and manual-review boundary sections. It also extracts source-row, causal-memory, wait-signal, context-overlay, evidence-source-contract, and object-pointer references into `source_ref_json` when those handles are already present in the reason contract. Fresh event-policy and playbook action reason contracts now preserve canonical source-row handles, and compact context-overlay reason sections now preserve `context_source` plus `context_overlay_id`, so action provenance can link announcement, bhavcopy, exchange, macro, and theme overlay evidence back to the compact source table. `advisory.action_recommender --repair-reason-contracts` can also rebuild persisted reason-contract metadata without changing action codes, ranking, portfolio state, or broker behavior, and its dry-run output reports before/after missing multi-context labels so operators can judge whether repair improves layered attribution. This is audit-only and has no ranking, portfolio, or broker authority.
   - `advisory.event_data_quality` now includes an action-provenance readiness gate. It checks whether final-action evidence nodes have source references, whether context-overlay provenance carries source-table links, whether provenance is fresh, and whether any provenance row accidentally carries broker authority. `advisory.action_evidence_provenance` now recognizes both exact `context_overlay_id`/`overlay_id` pointers and older source/date/class/direction context-overlay query references, and it deletes/rebuilds provenance for the same action keys before inserting refreshed rows so stale no-link audit nodes do not linger. A live 2026-06-21 bounded rebuild created 788 audit-only rows from 100 actions with no broker authority and raised context-overlay source-table coverage from 27% to 100% for the bounded sample. The wider 30-day rebuild then persisted 3,943 audit-only rows across 157 symbols, and the quality gate reported source-ref coverage 1.0, context source-table coverage 1.0, and zero broker-authority rows.

8. Keep action transitions stateful and deterministic.
   - LLM outputs can update watch/de-risk pressure, thesis notes, wait signals, or questions.
   - The deterministic action layer must decide whether a symbol can move from `WATCH` to `BUY`, `HOLD` to `PARTIAL_SELL`, or any other transition based on current position state, prior recommendation state, cooldowns, technical confirmation, risk, lifecycle, and execution gates.
- Final action reason contracts now include an `action_transition.transition_stability` audit that compares prior action, current action family, review-only source authority, position state, and technical confirmation. It marks repeat actions, safe non-executable transitions, insufficient prior history, and unstable flips such as entry-after-exit without fresh technical confirmation. `advisory.action_transition_evaluator` evaluates these transition classes against point-in-time Dhan forward returns and point-in-time NIFTY benchmark returns, persists benchmark/excess directional helpfulness fields, and is wired into model-training research evidence. Candidate transition policies require both absolute after-cost directional evidence and benchmark-excess directional evidence; raw-positive/no-excess outcomes are labelled `benchmark_beta_not_transition_alpha` and stay research-only instead of being confused with transition-policy alpha. Separately, the action recommender now has a narrow deterministic safety gate, controlled by `ACTION_TRANSITION_STABILITY_POLICY_GATE_ENABLED`, that downgrades broker-capable rows with explicit transition blockers to review-only `WATCH` or `REDUCE_EXPOSURE_REVIEW`. This does not create ranking promotion, portfolio authority, or broker execution.
   - Recommendation diagnostics now exposes those deterministic transition-safety downgrades as `transition_policy_gates`, includes the blocker counts and original/downgraded actions in text output, and can classify missing BUYs as `transition_stability_policy_gate_downgraded_broker_actions`. This keeps transition-safety behavior from being mistaken for global regime, macro, LLM, or technical-threshold suppression.
   - Fast `advisory.signal_refresh --from-context-overlays` rows now include a compact `source_contract` for the announcement/bhavcopy/exchange/macro/theme overlay that created the review-only WATCH or de-risk pressure. Final action reason contracts expose this as a dedicated `signal_refresh` evidence section, and action-evidence provenance can link it back to the compact source overlay table. Operator Health audits recent context signal-refresh rows for missing or malformed source contracts and points stale/legacy rows back to the bounded context-overlay refresh command. This keeps fast news/macro/bhavcopy reactions auditable without granting BUY/SELL, portfolio, or broker authority.

9. Build causal event memory before granting stronger event influence.
   - Treat event classes as time-series objects with merged duplicates, freshness, contradiction state, expected decay, sector/company sensitivity, and realized-outcome diagnostics.
   - Event memory can improve LLM context and watcher targeting, but it should still produce review-only watch/de-risk pressure until outcome evidence justifies bounded deterministic use.

## Current Implementation Direction

- Keep `advisory_market_regime` as a diagnostic input, not a universal buy/sell switch.
- Use `advisory_market_context_summary_daily` and `advisory_market_context_universe_daily` for breadth and top-context universe evidence.
- Use `advisory.regime_overlay` for review-only dynamic macro/news regime proposals.
- Rule-engine candidate generation and action consolidation no longer hard-block solely because a setup/global `regime_name` label is adverse. In the rule engine, blocked regime labels are persisted as soft `regime_blocked_context_only` audit rows unless `RULE_ENGINE_REGIME_LABEL_HARD_BLOCK_ENABLED=true`, and the configured `regime_fit` score weight is multiplied by `RULE_ENGINE_REGIME_FIT_WEIGHT_MULTIPLIER` (default `0.35`) so a single global label remains diagnostic instead of dominating technical/fundamental evidence. In action consolidation, hard blocking requires systemic macro-risk evidence (`STRESS`, `CRASH`, `HOSTILE`, `SHOCK`) or an explicitly re-enabled label/score/breadth/high-risk gate through `ACTION_MARKET_CONTEXT_REGIME_LABEL_HARD_BLOCK_ENABLED=true`, `ACTION_MARKET_CONTEXT_SCORE_RISK_OFF_HARD_BLOCK_ENABLED=true`, `ACTION_MARKET_CONTEXT_WEAK_BREADTH_HARD_BLOCK_ENABLED=true`, or `ACTION_MARKET_CONTEXT_HIGH_MACRO_RISK_HARD_BLOCK_ENABLED=true`; weak breadth, score-only risk-off, and ordinary `HIGH`/`RISK_OFF` macro-risk labels are sizing/caution haircuts by default. Top-ranked/benchmark/sector-leading symbols now count as a symbol-specific offset for score-only broad risk-off when `ACTION_MARKET_CONTEXT_LEADER_SOFTENS_SCORE_RISK_OFF_ENABLED=true`, so they receive a size reduction instead of Manual Review. Fresh positive context-overlay support can also soften score-only broad risk-off into a size reduction when `ACTION_MARKET_CONTEXT_CONTEXT_OVERLAY_OVERRIDE_ENABLED=true`; by default `ACTION_MARKET_CONTEXT_CONTEXT_OVERLAY_SOFTENS_ANY_SYMBOL_ENABLED=true` allows this even outside the top-leader bucket, but only for an existing technical/portfolio positive action and only when the source family and exact `context_class` are not classified as harmful/no-lift, negative after costs, horizon-inconsistent, or benchmark-unattributed. This does not override systemic hard macro-risk, does not create context-driven BUY authority, and remains fully visible in the recommendation reason contract. That contract now carries `multi_context_diagnostics`, separating breadth, macro stress, sector/symbol leadership, event-overlay alignment, and technical confirmation so the global regime label is one diagnostic field rather than the explanation. In hypothesis/playbook planning, weak-breadth hard-block mode is also overridden for top-ranked or benchmark/sector-leading symbols, score-only risk-off is not a hard downgrade unless `HYPOTHESIS_MARKET_CONTEXT_SCORE_RISK_OFF_HARD_BLOCK_ENABLED=true`, ordinary high macro-risk is not a hard downgrade unless `HYPOTHESIS_MARKET_CONTEXT_HIGH_MACRO_RISK_HARD_BLOCK_ENABLED=true`, and fresh positive symbol/sector context overlays can similarly prevent score-only broad risk-off from downgrading a positive playbook plan when `HYPOTHESIS_MARKET_CONTEXT_CONTEXT_OVERLAY_OVERRIDE_ENABLED=true`; by default `HYPOTHESIS_MARKET_CONTEXT_CONTEXT_OVERLAY_SOFTENS_ANY_SYMBOL_ENABLED=true` applies the same rule outside the top-leader bucket. Systemic hard macro-risk still downgrades positive playbook actions to watch/review evidence, and playbook/context overlays still have no portfolio or broker authority.
- Non-preferred regime labels also stay out of the rule-engine soft-failure threshold budget. The row still records `regime:*_not_preferred` and still receives the bounded `regime_fit` score impact, but the global label cannot be the extra soft failure that turns an otherwise valid technical/fundamental setup into a lower recommendation state.
- Use `advisory_news_theme_context_overlays` for review-only sector/theme pressure derived from active news themes. These rows state positive/negative sector pressure, matched news sources, suggested screeners, invalidation signals, holding profile, and `authority_scope=watchlist_pressure_only`; they do not bypass technical, liquidity, risk, lifecycle, or execution gates.
- Continuous news and announcement watchers consume those theme overlays as lower-priority watch targets by mapping affected sectors to the current market-context universe. Existing explicit watchlist/position rows still win over contextual rows, and non-material context matches are recorded as `context_observed` rather than escalated. Watcher target selection also uses persisted source-family reliability to exclude synthetic context families that have hurt, gone negative after costs, or behaved inconsistently across horizons; missing reliability evidence stays neutral and explicit watchlist/market-context targets are not filtered by this gate. Synthetic sector-mapped context targets are also checked against matching sector diagnostics, so harmful/no-lift, negative-after-cost, horizon-inconsistent, or benchmark-unattributed sector splits do not enter the fast watcher queue.
- Watcher target selection now also reads exact `context_class` diagnostics when they are available directly or inside `watch_reasons_json`. A noisy/harmful class inside an otherwise helpful family is excluded from synthetic context watcher queues, while explicit watchlist and broad market-context targets stay neutral.
- Runtime consumers prefer explicit context reliability `runtime_policy_contract` fields when available. A source family classified as helpful is not enough by itself: watcher synthetic context target selection, OHLCV watcher exchange-context priority, and watchlist priority require `allowed_runtime_uses.watch_priority=true` for positive/watch pressure, hypothesis/playbook risk-off softening requires `allowed_runtime_uses.watch_priority=true`, company-memory positive/watch pressure requires `allowed_runtime_uses.watch_priority=true`, action-consolidation positive context softening and trusted overlay-rule consumption also require `allowed_runtime_uses.watch_priority=true`, signal-quality promotion review creation requires `allowed_runtime_uses.watch_priority=true` before broad positive/watch family promotion is considered, and watcher negative context target selection plus signal-refresh/company-memory de-risk pressure require `allowed_runtime_uses.de_risk_review=true` or a protective exact context class. Sector reliability is a narrower suppressor/annotation only: a protective sector split cannot create de-risk permission if the family/class contract does not allow it. OHLCV exchange-context priority can also run for protective/de-risk context, but only as ordering metadata for already-monitored symbols. For action-consolidation trusted overlay-rule consumption, older rows without an explicit persisted contract are now annotation-only; regenerate context-overlay reliability evidence before expecting a reviewed rule to affect action ranking.
- Context overlays are also checked by `advisory.signal_refresh --from-context-overlays`; the older `--from-theme-context` flag remains a compatibility alias. Positive/watch overlays can create fast `WATCH` discovery rows only when the watchlist builder emits an active `WATCH_EVENT` or `WATCH_BREAKOUT` row; inactive `REJECT` rows and `suppress_*` audit rows are filtered out before signal creation. Sector-mapped negative theme overlays plus direct symbol-level announcement, exchange-event, and bhavcopy overlays can create `REDUCE_EXPOSURE_REVIEW` rows when they match existing watchlist or portfolio exposure. Context-overlay watchlist intake and signal refresh use date-only full-day cutoffs for daily runs and exact timestamp cutoffs for watcher/ad-hoc runs, so same-day overlay rows are included in daily refreshes without letting timestamped refreshes see later rows. Context-overlay watchlist intake may use persisted source-family reliability only to rank watch priority for `candidate_helpful` families. Allowed negative/de-risk signal-refresh rows now carry the source-family reliability classification/effect in their action payload, while harmful, negative-after-cost, horizon-inconsistent, or benchmark-unattributed families/classes are suppressed with samples in the run summary. Newer same-symbol negative direct context can suppress older positive/watch context intake, but this creates an inactive watchlist row only; it is not sell, portfolio, or broker authority. Action consolidation can consume recent signal-refresh rows as review-only candidates so watcher evidence reaches the Action Queue before a long full-advisory run finishes: positive rows become `WATCH`, negative rows become `REDUCE_EXPOSURE_REVIEW`, stop-policy rows become `TIGHTEN_STOP`, and unresolved rows remain `MANUAL_REVIEW`. All signal-refresh rows have `authority_scope=review_input_only`, `portfolio_authority=none`, `broker_execution_allowed=false`, and `full_advisory_required=true`.
- Negative context-overlay signal refresh now requires an explicit non-synthesized family runtime contract before a family-level `protective_candidate` label can create de-risk review pressure. Exact protective class evidence can still allow a row, but synthesized/legacy family contracts and bare protective labels are suppressed and reported in the refresh diagnostics. This keeps fast watcher evidence from acting on stale market-beta or legacy reliability rows.
- Context-overlay signal refresh now deduplicates identical same-symbol review-intent rows before affected-symbol accounting, persistence, sync-state writes, and Redis publication. The run summary carries raw-versus-deduped signal counts, so duplicate loader paths remain visible without inflating Action Queue pressure.
- Context-overlay watchlist intake now deduplicates by symbol first and then applies the global `WATCHLIST_CONTEXT_OVERLAY_LIMIT` by reliability-adjusted watch priority, not by ticker order. This prevents alphabetically early symbols from crowding out stronger news, macro, bhavcopy, or announcement pressure while preserving the watch-only/no-broker authority contract.
- Context-overlay watchlist intake also uses point-in-time `advisory_technical_daily` rows as a bounded actionability bonus when available. Liquidity, trend alignment, near-pivot state, relative strength, extension, and gap-behavior checks can lift a context row's rank by at most `WATCHLIST_CONTEXT_OVERLAY_TECHNICAL_PRIORITY_MAX_BONUS`; missing technical rows stay neutral rather than being silently dropped. The technical actionability fields are persisted in `watch_reasons_json` for audit, but they still do not create BUY, portfolio, sizing, or broker authority.
- Context-overlay watchlist rows now carry a `context_watchlist_builder_version` in `watch_reasons_json`, and the `--skip-if-current` guard requires active rows to match the current builder version. Ranking/selection changes therefore force a bounded context-watch rebuild instead of reusing a stale persisted snapshot that may still contain old symbol-order or missing-technical-priority behavior.
- When recommendation diagnostics sees positive/watch context-refresh targets but no persisted context watchlist snapshot, its runbook now inserts the narrow reconciliation command `python -m advisory.watchlist_builder --date YYYY-MM-DD --setup CONTEXT_OVERLAY_WATCH --rebuild --skip-if-current` between bounded signal refresh and full `all_advisory.sh`. The same skip guard is used by the pre-advisory wrapper and skips only when same-date active watch rows are at least as fresh as a matching `ok` context signal-refresh sync state and those active rows have complete `technical_confirmation_plan` metadata. Missing, stale, wrong-date sync state, or legacy rows missing confirmation plans force a rebuild. This persists only context-overlay watch rows and keeps portfolio/risk/lifecycle/broker state unchanged, making news/macro/bhavcopy discovery visible without forcing the whole long advisory path first.

- FINSABER: `https://arxiv.org/abs/2505.07078`. Supports the bull-market underparticipation / bear-market over-risk concern and the need for trend detection plus risk controls rather than more complex LLM prompting alone.

- TradingAgents: `https://arxiv.org/html/2412.20138v6`. Useful as a multi-role analysis reference, but Stockey keeps broker/execution authority outside LLM debate loops.
