Notes:
- Row 15's second control was designed wrong, and the way it failed is worth
  more than the trial itself. C2 re-shuffled the day's weights independently
  every morning, so it turned its entire book over daily (~160%/day) and bled
  ≈−55%/yr in costs alone. Every dead rule "beat" it by 5-6% a month at t up to
  +22. Had that been the only selection control — and it was the only one the
  pre-registration named — this row would have promoted four rules with no edge
  whatsoever to the holdout, with spectacular t-statistics. The fix (C3: the
  same permutation drawn ONCE per symbol instead of daily, so the control holds
  its positions) was added after the run and is diagnostics only, never a
  decision input for this row. The general lesson, which is the same one row 12
  learned about same-day controls: **a control must be matched on everything
  the rule is not being tested for — turnover included — or it is a straw man,
  and beating a straw man produces the largest t-statistics in the file.**
- Row 15's absolute returns are slightly optimistic for a reason that does not
  affect its paired verdicts: a symbol that stops trading simply leaves the
  eligible set, so a delisting is booked as a costless exit at the last known
  weight rather than as a loss. Signal and controls share the assumption
  exactly, so the differences are clean; the levels are not.
- The M in rows 12 and 13's prose ("~94", "~115") is NOT the number
  `research.CountM` computes from this file, which on 2026-09-07 is **1110**
  (Bonferroni bar t = 4.08). The prose figures counted only this session's own
  trials and left out the imported stockey monitoring families of rows 6-9,
  which are 855 trials between them. The tool's number is the one the file's
  own rule points at ("M = row count of distinct variations per dataset; the
  Bonferroni bar in backtest reports derives from it"), so it is the number
  reports must use. Two counter bugs were fixed the same day: it read only the
  FIRST `trials=` on a row (silently dropping row 9's second batch of 174) and
  it clamped an explicit `trials=0` up to 1.
- Row 14 is deliberately trials=0. Forecast-scalar fitting and correlation
  structure consult no performance number, so they test no hypothesis and
  consume no sample — the same reasoning that keeps Carver's own scalar table
  out of M. What row 14 DOES do is narrow the next trial (three families
  instead of twelve), and that narrowing is visible here rather than buried in
  a commit, because a reader must be able to see that the shortlist was chosen
  on correlation, not on returns.
- Rows 1–2 are inherited, ideas-first rules — the book's own out-of-sample
  evidence is their admission ticket; our backtests of them are *verification*,
  not selection, so they don't inflate M for selection purposes.
- Row 10 is treated the same way: Weinstein's stage definitions and 30-week
  window are published, fixed parameters, not fit to this dataset — building
  the classifier is verification tooling, not a selection trial. The one
  parameter not literally numeric in Weinstein's own book (the 4-week/±1%
  "flattens out" test) was fixed before looking at any NSE output; see
  `internal/stage`'s doc comment for exactly where that discretion entered,
  in case a future sensitivity check wants to revisit it.
- Everything we invent or tune locally DOES count toward M.
- Row 13 was run IN-SAMPLE on a consumed dataset at the operator's explicit
  request, after the constraint was stated. That is a legitimate use of spent
  data for exactly one purpose — falsification — and it did falsify. Had it
  come back positive, it would have proved nothing and the correct next step
  would still have been a forward-only test. Do not cite a positive in-sample
  re-run of a hypothesis this dataset generated as evidence for anything.
- Row 12's panic arm carries a second control that rows 1-11 do not: a random
  OTHER candidate from the SAME day. A nearby-date control cannot test a
  cross-sectional ranking, because every name on a panic day shares the day's
  market move — without the same-day control, "buy the worst fallers" would
  have scored the market's bounce and looked like stock selection.
- Row 11 is an externally-supplied pattern evaluated on request, and is the
  file's one deliberate Law-1 violation: it was tested WITHOUT an economic
  story. That is defensible only because the outcome was a rejection. Had it
  produced a positive result, the missing story would have made the result
  unusable — no story, no way to tell an edge from the luckiest of M scans.
  Do not treat this row as precedent for testing storyless ideas that someone
  hopes will work.
- Rows 3–5 are imported from the stockey session's research (memory +
  `advisory/` experiments, 2026-06/07): same underlying NSE data, so their
  trials count toward M here. Their 2020-01→2021-07 holdout is burned for the
  ensemble family (see `research/holdout_burns.json`): our Part B for that
  family must start 2021-08 or later.
